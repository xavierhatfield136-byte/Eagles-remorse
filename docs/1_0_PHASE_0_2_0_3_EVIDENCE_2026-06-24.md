# Phase 0.2 And 0.3 Evidence — 2026-06-24

## 0.2 Save compatibility

- Advanced the checkpoint schema from 1 to 2.
- Added `CampaignSaveContract`, which reflectively inventories every public
  checkpoint field and classifies it as authoritative live, debug/readout-only,
  future/model-only, or migration metadata.
- Added explicit schema-v1 defaults for missing faction fleets, player fleet,
  production queues, mining cargo, territory, reputation history, environment,
  strategic resources, and strike inventory.
- Unknown top-level enums and malformed nested enums use safe fallbacks.
- Migration load does not mutate the source file.
- Before migration commit, the source is retained as a versioned backup.
- The migrated checkpoint is saved, reloaded, and verified before acceptance; a
  failed verification restores the source.
- Added a clear recovery banner and durable `campaign.save_recovery` event.
- Added `test/fixtures/campaign_schema_v1.properties`.
- The end-to-end migration test proves load, travel, tactical entry, ship
  purchase, ship construction queueing, resave, first reload, and second reload.

## 0.3 Release telemetry

Durable structured reason families:

- `campaign.fleet.created`
- `campaign.fleet.destroyed`
- `campaign.fleet.disappeared`
- `campaign.ownership.changed`
- `campaign.production.start`
- `campaign.production.stop`
- `campaign.mining.departure`
- `campaign.mining.return`
- `campaign.mission.success`
- `campaign.failure`
- `campaign.strike.denied`
- `campaign.save_recovery`

Telemetry is restricted to campaign time, sector, stable IDs, enums, bounded
labels, and reason codes. Sanitization redacts email-like values and user
filesystem paths and truncates unbounded values. The contract explicitly excludes
credentials, usernames, email addresses, filesystem paths, and machine IDs.
